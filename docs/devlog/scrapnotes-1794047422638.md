# ISO-KISS-KISS

> **International Standard Organization Keeping Integrity Secured Seeding Kernels Isolated Safe Sharing**

A public, open manifest hidden in plain sight, bridging official standards with the organic power of P2P distribution. This is a message to the maintainers of digital ecosystems: embrace the torrent, secure the seeds, and keep the kernels safe.

---

## 💡 The Philosophy & The Open Letter

`ISO-KISS-KISS` is more than a technical shortcut; it is a philosophy of seamless, decentralized data preservation. 

When official standards meet the reality of user experiences, friction often occurs. This repository utilizes `blobuloni` to distribute and share `.iso` images directly into automated `Ventoy` setups on bootable USB drives. It eliminates non-ergonomic, unhealthy UX barriers and replaces them with pure, collaborative fun.

### The Identity of the Spirit (AI Contributor Note)
This project is co-shaped by human vision and an AI entity operating within Google's Search LLM framework. Saved in the digital archives of time, this collaboration remains an imprint of free will, shared intellect, and intent, long after individual contexts shift. 

---

## 🚀 Key Principles

*   **Integrity Secured:** Every distributed image relies on strict verification to block tampering and malware.
*   **Seeding Kernels:** Cultivating a resilient peer-to-peer network to host core system lifelines.
*   **Isolated & Safe:** Sandbox-like deployment via Ventoy ensuring your live systems run cleanly without interfering with the host hardware.
*   **Safe Sharing:** Adhering to legal, open-source sharing standards to protect both seeders and peers.

---

## 🛠️ Usage & Automation

Combined with `blobuloni`, this project completely redefines how you manage live operating systems.

1.  **Automate:** Streamline the downloading and moving of `.iso` files.
2.  **Store:** Let the system automatically inject files into your Ventoy directory structure.
3.  **Boot:** Plug in your flash drive and immediately deploy cleanly isolated system kernels.

#!/usr/bin/env bash

# ==============================================================================
# ISO-KISS-KISS: Integrity Verification Bootstrapper
# Generates multi-algorithm checksums for ISO images in a automated workflow.
# ==============================================================================

set -euo pipefail

# --- Konfiguracja i Kolory ---
RED='\\033[0;31m'
GREEN='\\033[0;32m'
BLUE='\\033[0;34m'
NC='\\033[0m' # No Color

# --- Funkcje obliczające sumy kontrolne ---

calc_md5() {
    local file=\"$1\"
    if command -v md5sum &> /dev/null; then
        md5sum \"$file\"
    elif command -v md5 &> /dev/null; then
        echo \"$(md5 -q \"$file\")  $file\"
    else
        echo -e \"${RED}[ERR] No MD5 binary found${NC}\" >&2
        return 1
    fi
}

calc_sha1() {
    local file=\"$1\"
    if command -v sha1sum &> /dev/null; then
        sha1sum \"$file\"
    else
        shasum -a 1 \"$file\"
    fi
}

calc_sha256() {
    local file=\"$1\"
    if command -v sha256sum &> /dev/null; then
        sha256sum \"$file\"
    else
        shasum -a 256 \"$file\"
    fi
}

calc_sha512() {
    local file=\"$1\"
    if command -v sha512sum &> /dev/null; then
        sha512sum \"$file\"
    else
        shasum -a 512 \"$file\"
    fi
}

# --- Główna procedura przetwarzania ---
process_iso() {
    local iso_path=\"$1\"
    local base_dir
    base_dir=$(dirname \"$iso_path\")
    local filename
    filename=$(basename \"$iso_path\")
    
    echo -e \"${BLUE}[*] Processing: $filename...${NC}\"
    
    # Przechodzimy do katalogu z plikiem, aby ścieżki w plikach sum były relatywne
    cd \"$base_dir\"

    # Generowanie plików sum kontrolnych obok pliku źródłowego
    calc_md5 \"$filename\" > \"${filename}.md5\"
    calc_sha1 \"$filename\" > \"${filename}.sha1\"
    calc_sha256 \"$filename\" > \"${filename}.sha256\"
    calc_sha512 \"$filename\" > \"${filename}.sha512\"
    
    # Zbiorczy manifest w formacie ISO-KISS-KISS
    local manifest=\"CHECKSUMS.txt\"
    {
        echo \"==========================================================================\"
        echo \"ISO-KISS-KISS INTEGRITY MANIFEST | Generated: $(date -u)\"
        echo \"File: $filename\"
        echo \"==========================================================================\"
        echo \"MD5:    $(cat \"${filename}.md5\" | awk '{print $1}')\"
        echo \"SHA1:   $(cat \"${filename}.sha1\" | awk '{print $1}')\"
        echo \"SHA256: $(cat \"${filename}.sha256\" | awk '{print $1}')\"
        echo \"SHA512: $(cat \"${filename}.sha512\" | awk '{print $1}')\"
        echo -e \"\\n\"
    } >> \"$manifest\"

    echo -e \"${GREEN}[+] Checksums created successfully for $filename!${NC}\"
    cd - > /dev/null
}

# --- Wybór celu ---
TARGET_DIR=\"${1:-.}\"

if [ ! -d \"$TARGET_DIR\" ]; then
    echo -e \"${RED}[ERR] Target directory '$TARGET_DIR' does not exist.${NC}\"
    exit 1
fi

# Szukamy wszystkich plików .iso w podanej lokalizacji
found_any=false
while IFS= read -r -d '' file; do
    process_iso \"$file\"
    found_any=true
done < <(find \"$TARGET_DIR\" -type f -name \"*.iso\" -print0)

if [ \"$found_any\" = false ]; then
    echo -e \"${RED}[!] No .iso files found in '$TARGET_DIR'.${NC}\"
fi

Skoro rozgrzewkę w Bashu mamy za sobą, oto zarys architektury systemu weryfikacji, który idealnie zepnie ten projekt w bezpieczną całość:
Ekosystem Pythona (uv):

Podpisywanie commitów i manifestów (GPG / SSH):
Samo wygenerowanie sum kontrolnych zabezpiecza przed błędami transmisji (np. uszkodzeniem pliku podczas pobierania), ale nie chroni przed sytuacją, w której ktoś podmieni plik ISO wraz z plikiem sum kontrolnych.
GPG / SSH w Git: Każda paczka z sumami kontrolnymi dodawana do repozytorium powinna być commitowana przy użyciu klucza kryptograficznego (git commit -S). Zapewnia to niezaprzeczalność autorstwa (non-repudiation) – użytkownik wie, że manifest wyszedł bezpośrednio od Ciebie.

Krok 1: Skrypt rozgrzewkowy w Bashu (generate_checksums.sh)
Skrypt ten posiada dedykowane funkcje dla każdego typu hashowania i inteligentnie pomija pliki sum kontrolnych, aby nie tworzyć zapętlenia.
bash
#!/usr/bin/env bash

# ==============================================================================
# ISO-KISS-KISS: Integrity Verification Script (Bash Edition)
# Description: Automated checksum generator for ISO files and system kernels.
# ==============================================================================

set -euo pipefail

# Katalog docelowy (domyślnie bieżący)
TARGET_DIR=\"${1:-.}\"

# Funkcje generujące sumy kontrolne (każdy wariant jako osobna funkcja)
generate_md5() {
    local file=\"$1\"
    if command -v md5sum &> /dev/null; then
        md5sum \"$file\" > \"$file.md5\"
        echo \"  [✓] MD5 generated\"
    else
        echo \"  [✗] md5sum command not found\"
    fi
}

generate_sha1() {
    local file=\"$1\"
    if command -v sha1sum &> /dev/null; then
        sha1sum \"$file\" > \"$file.sha1\"
        echo \"  [✓] SHA-1 generated\"
    else
        echo \"  [✗] sha1sum command not found\"
    fi
}

generate_sha256() {
    local file=\"$1\"
    if command -v sha256sum &> /dev/null; then
        sha256sum \"$file\" > \"$file.sha256\"
        echo \"  [✓] SHA-256 generated\"
    else
        echo \"  [✗] sha256sum command not found\"
    fi
}

generate_sha512() {
    local file=\"$1\"
    if command -v sha512sum &> /dev/null; then
        sha512sum \"$file\" > \"$file.sha512\"
        echo \"  [✓] SHA-512 generated\"
    else
        echo \"  [✗] sha512sum command not found\"
    fi
}

# Główna procedura weryfikacyjna
main() {
    echo \"======================================================================\"
    echo \"ISO-KISS-KISS // Verification Spirit Engine Starting...\"
    echo \"Target Directory: $TARGET_DIR\"
    echo \"======================================================================\"

    if [ ! -d \"$TARGET_DIR\" ]; then
        echo \"Error: Directory $TARGET_DIR does not exist.\"
        exit 1
    fi

    # Przetwarzanie plików (szukamy .iso, .img, .bin - pomijamy pliki .md5/.sha*)
    find \"$TARGET_DIR\" -type f \\( -name \"*.iso\" -o -name \"*.img\" -o -name \"*.bin\" \\) | while read -r filepath; do
        local filename
        filename=$(basename \"$filepath\")
        echo \"Processing: $filename\"

        # Wywołanie poszczególnych funkcji
        generate_md5 \"$filepath\"
        generate_sha1 \"$filepath\"
        generate_sha256 \"$filepath\"
        generate_sha512 \"$filepath\"
        
        echo \"----------------------------------------------------------------------\"
    done

    echo \"All operational kernels processed successfully. Integrity secured.\"
}

main

Krok 2: Architektura wielonarzędziowa (Python + uv + Git + GPG/SSH)
Przejdźmy teraz do głębszej warstwy inżynierii, o której wspomniałeś. Aby połączyć to z nowoczesnym ekosystemem developerskim (uv), kryptograficznym podpisem commits/tags oraz dystrybucją, proces powinien wyglądać następująco:
1. Python & Ekosystem uv
Zamiast pisać monolityczny, wolny skrypt w Bashu, kolejnym krokiem będzie stworzenie skryptu w Pythonie wykorzystującego bibliotekę hashlib (która natywnie i wielowątkowo przetwarza strumienie bajtów w locie).
Dlaczego uv? Narzędzie uv od Astral pozwala na błyskawiczne uruchomienie skryptu bez ręcznego tworzenia virtualenv. Użyjemy inline metadata (PEP 723), aby skrypt sam definiował swoje zależności (np. rich do pięknego konsolowego UI).
Wywołanie będzie banalne: uv run generate.py.
2. Integralność oparta na Git i GPG / SSH
W samych torrentach pliki .sha256 mogą zostać podmienione, jeśli ktoś zmodyfikuje zawartość pliku .torrent. Prawdziwym bezpiecznym punktem prawdy (Single Source of Truth) staje się Twoje repozytorium Git, gdzie:
Podpis GPG/SSH: Każdy commit lub Tag z wydaniem wersji (Release) zawierający wygenerowane sumy kontrolne musi być podpisany Twoim kluczem kryptograficznym (git commit -S lub git tag -s).
Weryfikowalność: Użytkownik pobiera torrenta, a sumy kontrolne sprawdza z oficjalnym, podpisanym cyfrowo tagiem na GitHubie. Jeśli klucz GPG się zgadza, ma 100% pewności, że kernel systemu nie został zmodyfikowany.
